# v0.4.2 — tidy model catalogues

This patch release makes configured model profiles removable directly from the
TUI without disturbing the provider catalogue or unrelated configuration.

## Highlights

- `/model` now supports `Delete` and `Ctrl-D` on the highlighted configured
  model.
- Removal is protected by a host-owned confirmation showing the exact model and
  provider, and cancel returns to the same filter and cursor position.
- The matching `[[model]]` entry is removed surgically from `models.toml` while
  preserving unrelated models, comments, voice, retrieval, and future settings.
- A model-specific saved credential is removed with the profile; provider-wide
  and other model credentials remain intact.
- Removing the pending model clears that pending selection and refreshes the
  live picker immediately. Running sessions are not interrupted.
- ACP/provider catalogue entries remain available in `/provider`, so a deleted
  model can be discovered and added again later.

## Accessibility and reliability

- The cooked `--accessible` / `--plain` interface accepts `delete` in model and
  API-key pickers and announces the confirmation semantics.
- Failed edits leave the existing model configuration untouched, malformed
  configuration is never overwritten, and normal write failures roll back the
  accompanying credential change.
- The full TUI suite covers keyboard mapping, exact filtered-row selection,
  cancellation, confirmation, and the visible removal hint.
