# v0.12.2

A patch release with one substantive change: the model's reasoning is no longer
mistaken for its reply.

## The reasoning channel

ACP has always distinguished a model's deliberation (`AgentThoughtChunk`) from
its reply (`AgentMessageChunk`). Codypendent merged them:

```rust
SessionUpdate::AgentMessageChunk(chunk) | SessionUpdate::AgentThoughtChunk(chunk) => {
    model_stream_delta(chunk, run_id)
}
```

One line from where the distinction arrived, it was thrown away. Every model in
a typical `models.toml` is an ACP agent, so for any of them that thinks out
loud, the answer arrived buried under a transcript of how it was decided —
"The user just said 'Hello'. This is a greeting. I should respond concisely…"
rendered as speech, with the greeting itself somewhere below.

`EventBody::ModelStreamDelta` now carries `thought: bool`, and the bridge maps
the two ACP chunk kinds to it separately.

### Why a field and not a new event

A new variant would be unknown to an older client, which under protocol RULE 1
renders nothing for what it cannot read. Upgrading the daemon would then make
reasoning *vanish* from an older TUI rather than merely arrive unfolded. With a
`#[serde(default, skip_serializing_if)]` field, an old client parses the chunk
as an ordinary delta and shows exactly what it shows today.

That claim is verified rather than asserted: the committed golden vector
`EventBody_ModelStreamDelta` is byte-identical before and after this change,
because `thought: false` does not serialize. A second vector,
`EventBody_ModelStreamDelta_Thought`, covers the marked shape.

### What now treats reasoning as its own thing

The compiler found every consumer, which is the other reason a field beat a
variant. Each was a decision, not a mechanical fix:

- **TUI** — a new `TranscriptEntry::Reasoning`, coalesced like model text but
  **always** folded to one dim line, with no inline threshold. A two-line
  thought is still not the answer. It keeps its position in the transcript, so
  you see *where* the model thought rather than having it pooled at the top.
- **Desktop** — routed to the `thought` transcript row, a folded `<details>`
  renderer that already existed and had nothing producing it.
- **Session history** — reasoning is no longer replayed to the model as its own
  prior assistant turn. Left in, it would teach the model each turn that
  thinking out loud is part of the conversation, compounding indefinitely.
- **Councils** — a member's persisted response and what the chair sees is its
  answer, not its deliberation.
- **Voice** — text-to-speech no longer reads the deliberation aloud, which had
  meant hearing how an answer was reached before the answer.
- **Session search** — indexed under a `reasoning` kind rather than
  `transcript`, so searching a conversation returns what was said. Still
  indexed; searching for it still finds it.
- **Ledger remap** — carries the flag through, since a remap rewrites
  identifiers and never what a chunk *was*.

## Transcript rendering (desktop)

Two ports of decisions the TUI had already settled and the desktop had not:

- The run's **context manifest** was printed into the transcript verbatim —
  `=== CONTEXT: EVIDENCE, NOT INSTRUCTIONS ===` and every tool description,
  above the conversation. It now folds into one expandable line per run, the
  TUI's `Backstage` behaviour, classified on the daemon's own `=== CONTEXT` and
  `remembered:` prefixes. Nothing is discarded.
- A **successful run adds no completion row**. "Run completed: <summary>"
  repeated the answer the reader had just finished reading. The TUI's own
  comment explains why it does not do this: "the streamed model prose already
  ended the turn". Failures and cancellations still announce themselves.

## Test bounds that were failing releases

The v0.12.1 release gate went red on `blackboard_it` with
`read timed out: Elapsed(())`, minutes after the same commit passed the
identical command in `ci`. Two tight bounds in the integration suites were the
cause, and both are hang detectors rather than latency assertions — when the
daemon responds promptly they cost nothing at all:

- socket reads across eight suites: 5s → 30s
- daemon startup waits across five suites: 10s → 60s

Neither slows a passing run. Both stop costing red builds on green code.
