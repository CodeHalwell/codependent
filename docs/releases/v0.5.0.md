# v0.5.0 — the wires get attached

v0.5.0 is the repair release for the [2026-08-13 product review](../reviews/2026-08-13-product-review.md).

That review's finding was not a list of bugs. It was that **three consecutive
reviews, a month apart, reached the same conclusion**: engines were built,
tested and documented, and the last call site connecting them to the model or
the user was never attached. This release attaches them.

## Security — read this first

**A daemon connection had no principal.** `client_id` and `ClientRole` were both
asserted by the client in plaintext and the connection defaulted to
`Controller`. Demonstrated on the wire against a live daemon: a fresh,
never-attached client read another session's entire event history, and
**approved another client's parked `shell.run` command, which then executed** —
an approval-gate bypass.

Identity now comes from the transport. `SO_PEERCRED` is read at accept time,
before the first byte, so a client cannot forge it; `client_id` is demoted to a
correlation token that confers nothing. Sessions record their owner (migration
`0031`), and every by-id read and subscription re-derives permission from what
the server stored. A refusal is byte-identical to "does not exist", so a caller
cannot enumerate.

`crates/daemon/tests/multi_user_it.rs` pins all six guarantees, each verified
failing against the previous behaviour.

Two related fixes: the daemon no longer chmods a socket directory it does not
own (setting `CODYPENDENT_SOCKET=/tmp/x.sock` — which the product's own error
message recommends — made the machine's shared `/tmp` private to one user), and
`codypendent models add` no longer destroys the rest of `models.toml`.

## The ten shipped outcomes

- **TUI.** Tool cards and diffs from earlier turns are expandable again — the
  fold cursor is a `(run, entry)` address, so from the second message onward the
  already-written diff renderer is no longer dead. The command palette works
  during first-run setup (`/` was being swallowed). The Help overlay can scroll
  to its last binding instead of drawing a third of them off the bottom, and no
  longer collides key labels with descriptions. Consent dialogs pin their
  decision controls to the last row — at 60x12 the Antigravity trust prompt
  previously showed no decline control at all.
- **ACP.** `codypendent acp serve` answered **every** `session/prompt` with a
  JSON-RPC error carrying a Rust `Debug` dump: `AttachSession` is answered with
  the catch-up snapshot, never `CommandAccepted`, and the ACP bridge was the one
  caller demanding the latter.
- **Model selection.** Anthropic is genuinely wired rather than catalog-only.
  `models list-providers` exists — the `models add` help text pointed at it and
  it had never been added. Catalog metadata corrected against live sources per
  model family; a provider's self-reported context window is now clamped instead
  of being forwarded verbatim as Ollama's `num_ctx`.
- **Retrieval.** The funnel now narrows what the model is offered. Before, two
  unrelated objectives produced byte-identical 21-tool arrays; the code said so
  outright ("stays static and fully advertised — ALWAYS"). A documentation
  objective and a CI objective now receive different tool sets, and the four
  `docs.*` tools reach the model at all — they were dispatchable and absent from
  the catalog, so no agent could call the doc-writer.
- **Code graph.** `graph.callers_of`, `graph.blast_radius` and
  `graph.tests_covering` are model-callable tools. They had existed, tested, with
  doc comments naming them as those exact tools, and no caller but their own
  test.
- **Council.** A member's real failure reason survives (`RunStateChanged{Failed}`
  was beating the `RunCompleted` arm that carried it), and quorum is a majority
  rather than a hard-coded `2`.
- **Blackboard / kanban.** Three spellings of one checkout minted three separate
  boards, so a card written through one was permanently invisible from another.
  Non-task kinds are refused at board scope instead of stored invisibly while
  still consuming an ordinal.
- **Voice.** Outbound TTS had **no privacy gate**: every assistant turn, source
  code included, was POSTed to the hosted speech endpoint regardless of policy,
  while inbound audio was carefully checked. The same classification gate now
  runs in both directions. Transcription and speech API keys are settable from
  `/keys` — the user guide had documented this for a target that did not exist.
- **Evals.** The harness scored **passes for runs that never executed** (cases
  built only from `file-unchanged` are free when nothing happens) and, worse,
  **failures for runs that succeeded** — it diffed the wrong directory, since
  writing runs are isolated onto a worktree that is never merged back. Both
  fixed; that number gates promotion.

## New in this release

- **Executable skills** (`0026`) — a `wasmi` guest with fuel, memory and
  wall-clock ceilings that terminate, no WASI, and `read_file` brokered through
  a capability gate whose grant type has no public constructor. Package content
  is re-hashed before every run.
- **Live code graph** (outcome 14) — the filesystem watcher is armed. An
  uncommitted edit is visible to the next tool call without a commit or a
  restart; the graph previously only moved when `HEAD` did, so the agent's own
  edits were invisible to it.
- **Delegation** (`0028`) — the workflow frontier runs concurrently, bounded by
  `budget.maximum_agents` (validated since Phase 5 and read by nothing), with
  worktree isolation, `patch.consolidate` merge-back, and worker-branch reclaim.
- **Compounding memory** (`0029`) — the governed learning ledger reaches a run's
  context instead of being written and never read; memories can be corrected and
  forgotten with a durable audit. Two unrelated failures no longer supersede each
  other.
- **Docs round-trip** (`0030`) — the PR target validates before it pushes (it
  used to create and push a branch, then fail), persists the PR handle, and
  reflects merge status back onto the document.
- **Live measured routing** (`0025`) and **the ledger** (`0032`) — run usage and
  timings are recorded rather than discarded by a `.map(|_| ())`.
- **Hooks** (`0027`) — parser, verdict lattice and approval-reentry types.
  **Not yet dispatchable — see below.**

## Known limitations — what this release does NOT do

Stated plainly, because the review this release answers exists because such
things were previously left implied.

- **Hooks cannot fire.** Outcome 13 has its parser, its verdict lattice (two
  conflicting rewrites deny) and a type wall that makes approval-inheritance
  unrepresentable — and no dispatch site. Nothing calls a hook.
- **WASM skills have no invocation path yet.** `SkillRunner` is complete and
  tested; the `skills.run` tool that would let an agent reach it is not landed.
- **TTS/STT are hosted-only, not built-in.** No audio crates ship. Capture and
  playback shell out to `rec`/`arecord`/`ffmpeg` and a user-named player.
- **The promotion evidence path is still caller-asserted.** `codypendent eval
  run --candidate` writes `eval_suite_reports` directly into the daemon's SQLite
  rather than over the socket, so the daemon's server-side check is bypassed in
  practice. `CommandBody::SubmitEvalEvidence` exists and has zero callers.
  Migrating it makes a running daemon a hard dependency of that command — a
  product decision, deliberately not taken here.
- **`UiRunProjection.cost` is still `None`** even though cost is now measured.
- One test, `remote_ui_plugins::…record_repair_fails`, fails when the suite runs
  as **root** — it chmods a directory `0500` to inject a failure, which does not
  stop root. It fails identically at v0.4.5 and is not a regression.
