# v0.6.0 — the code graph stops being Rust-only, and the review that found out why

Cut from `claude/review-repair-twenty-outcomes-5fynno` (PR #65), based on
`c255bec` (v0.5.1). Ten commits, 136 files.

Two things happened in this release: a twenty-outcome review of the whole
product, and the repairs it justified. The review is in
[`docs/reviews/2026-08-13-r4-product-review.md`](../reviews/2026-08-13-r4-product-review.md);
what it repaired is in
[`2026-08-13-r4-repairs.md`](../reviews/2026-08-13-r4-repairs.md). Read the
synthesis's §1 first — it explains why three previous reviews reached the right
diagnosis and it still came back.

---

## The headline: the code graph now folds more than Rust

`tree-sitter-rust` was the only grammar in the workspace, and the scanner
rejected any file whose extension was not `rs`. On a repository of Python and
React — no Rust in it at all — the graph was **empty by construction, and
nothing said so.** The DAG viewer simply showed nothing.

- **Four grammars**: Rust, Python, TypeScript/TSX, JavaScript.
  `codegraph::language_for` is the single definition of "a file the graph can
  hold" — the parser dispatches on it and the scanner filters on it, so the two
  cannot drift into disagreeing about which files count.
- **`codypendent graph build | status | show`** — the graph is no longer only a
  side effect of opening a session. `build` reports what it walked, what it
  folded per language, what it ignored, and which extensions no grammar covers.
  A repository the extractor cannot read is told exactly that.
- **`doctor` warns on an empty graph** and names the command; `index rebuild`
  now says plainly that it does **not** build the code graph, which it never did.

## Agent-defined edges

`upsert_semantic_edges` had shipped, tested and documented, called by nothing
but its own test file. `graph.assert_edge` now lets a run assert what
tree-sitter cannot see — a route handler to the service it dispatches to — with
a required rationale kept as provenance, advertised in the catalog rather than
merely dispatchable, and scoped to the run's repository identity.

An agent's guess must never outrank the compiler, so `EvidenceKind::AgentAsserted`
sits at **0.40**, below syntax inference, and supersession changed from an
unconditional `DELETE` to "supersede only strictly lower confidence".

Three defects were found in that work by review on the PR and fixed before this
release, two of them serious:

- A **full rebuild destroyed every agent assertion.** `clear_repository` wiped
  all nodes and edges with no evidence filter. It is gone: a rebuild now refolds
  in place and retires only paths the walk no longer sees.
- Retiring a symbol deleted only its **incoming** edges, so one assertion plus
  one signature change left a dangling foreign key and **every later fold of
  that repository failed**.
- A dirty tree was stamped with the bare commit, so `graph status` called a
  just-built graph stale.

## The chat window

- Inline code inside a **table cell** was dropped from the cell and flushed into
  a paragraph after the table (`main.pycore/config.pycore/database.py…`). Cells
  now keep their spans, so `code`, **bold** and *italic* survive in a table.
- Column widths are shared **by need**: a two-column table on a wide terminal
  used to ellipsise its prose at 45 columns while the narrow column beside it
  used 16 of its own 45.
- Prose wraps at **spaces**, not mid-word, and a wrapped paragraph keeps one
  left edge — continuation rows line up under the text rather than under the rail.
- One blank line between blocks. Everything butted together before.

## Everything else the review repaired

The full list with evidence is in the repairs document. The largest were:

- **Repository identity** — "which repository is this" was re-derived at six
  call sites from four different inputs, and every disagreement surfaced to the
  user as an empty result. Documents an agent wrote were orphaned into a deleted
  worktree; `graph.*` answered "no results" in the default mode; a board forked
  per subdirectory. One accessor now, with the backing field private.
- **The WASM wall clock was not enforced** against a guest looping on host
  calls: a declared 1s ceiling overran by **166.8 seconds** and returned `Ok`.
- **A skill package promoted itself to first-party trust** with one line of its
  own TOML.
- **`PublishDocument` skipped its owner check** — a cross-uid confused deputy
  and an enumeration oracle. Ownership is now one choke point ahead of dispatch,
  which also caught `InstallUiPlugin` putting arbitrary code into the worker
  runtime gated only on a client-asserted role.
- **The eval gate scored 3/13 and printed `PASSED`** — the stub skipped step 0
  of every case, and the comparator only failed on a drop. It now fails on a
  change in either direction, on a changed case set, on corpus size, and on a
  fail-to-pass flip.
- **Measured tokens rendered as `? unsupported event`** in the transcript.

## Upgrading

```sh
codypendent update v0.6.0
```

or

```sh
curl -fsSL https://raw.githubusercontent.com/CodeHalwell/codypendent/main/install.sh | bash -s -- v0.6.0
```

`install.sh` requires the GitHub CLI (`gh`) on `PATH`. The VS Code extension's
`package.json` moves 0.4.2 → 0.6.0; it had drifted five releases behind.

Migrations: none added. `migrations/README.md` records that `0026`/`0027`
document writers that do not exist — the tables have no writer, so skill
execution and hook dispatch still leave no audit record.

## What this release does NOT do

Kept honest deliberately; each is a real gap a user can hit.

- **Executable skills still cannot be run by a user.** The WASM host is real and
  its ceilings now bite, but `SkillRunner` has no production caller.
- **Hooks never dispatch.** A hook planted in a repository produced
  `hooks 0 / hook_dispatches 0` against a live daemon. The three verbs work
  in-library only.
- **Delegation's merged diff is unreachable.** Workers fan out, isolate, and
  consolidate into one correct diff, and no command in the product will show it.
- **Memory cannot be inspected, edited or deleted from any client.** Five wire
  commands and their handlers work when driven directly; no client sends them.
- **Docs merge status reaches no user surface**, and a draft unmerged PR still
  sets a document's status to `published`.
- **Nothing about audio is built-in** — no audio crate is in the workspace. TTS
  and STT work only against a configured remote endpoint, and `local = true`
  disables the privacy gate without verifying the endpoint is local.
- **Routing still lets the catalog's advertised price feed the decision**, never
  re-measures latency or cost, and memory extraction bypasses the router.
- **The extension has no `CodeGraph*` type** — `graph` is a CLI surface only.
- **The code graph does not extract Python decorators, JSX element usage, base
  classes, or re-export chains**, and a FastAPI `@app.get` handler is a plain
  `Function`; `CodeNodeKind::Endpoint` exists and is deliberately unpopulated.
  No real FastAPI or React repository was folded — only fixtures.
- **MCP is two spec revisions behind** a breaking change (`2025-06-18` vs
  `2026-07-28`), and `cargo deny`'s `unsound` scope is still unset, which hides
  RUSTSEC-2026-0255.
- **`org`/`workspace` scopes are not enforcement axes.** What ships is per-OS-user
  isolation on a single local daemon.
