# v0.12.4

Everything since v0.12.2. The v0.12.3 notes describe work that was committed
but never tagged, so this release carries it, and this file is the complete
account.

**If you are on v0.12.2, bundle export and import do not work at all** — see
the first entry under Broken on arrival. That alone is the reason to upgrade;
the security list below is the rest of it.

## Untrusted input that reached further than intended

**A tar entry could ship a setuid file into the runner's tree.** The
materializer screens an untrusted archive and then applied that archive's file
modes verbatim: `0o4755` produced a setuid file, and setgid, sticky and
group/world-writable bits came through the same way, into a tree the runner is
about to execute from. Modes are masked to owner-writable, group/other
read-execute — which clears all of it while preserving the only distinction
anything downstream needs.

**An Observer could obtain a signed write.** `presign_object_url` authorized
`DownloadObject` regardless of the requested method, and every role may
download — so a read-only principal could ask for a PUT presign and receive a
signed write into the organization's bucket namespace, bypassing both
`upload_object`'s Contributor gate and its content-hash verification. The verb
now picks the gate, and an unrecognized verb is refused rather than mapped onto
the weakest one.

**Webhook replay suppression could be walked past one re-casing at a time.**
The replay key hashed the signature *header* string, and `verify_signature`
hex-decodes case-insensitively — so a captured delivery re-verified under any
case permutation of its hex, each minting a fresh fingerprint. It hashes the
body now, as the key's own name always said.

**Revoked secret leases were resurrected by asking again.** `issue_key` is
derived from the request context, so a revoked principal re-requesting the same
capability landed on the same row — and the renew path cleared `state` and
`revoked_at` unconditionally. Redeem already refused a revoked lease; refusing
only there meant revoke → re-issue → redeem walked straight around the kill
switch.

**Suspended and deleted users kept minting access tokens.** `refresh` loaded
the user only to read a display name and never consulted `state`, so suspension
was a no-op for anyone holding a 30-day refresh token. `UserState::is_active` —
documented as "whether the account may act" — had **no production callers
anywhere in the workspace**.

**`git push origin +main` and `git push -d` bypassed policy.** A leading `+` on
a refspec forces the push, and `-d` is git's shorthand for `--delete`, which
the `git branch` arm of the same check already matched while the `git push` arm
did not. Both fell through to the generic *reusable* approval path, so one
approved `git push *` pattern auto-approved force pushes and branch deletions
from then on.

**An unreadable classification ceiling authorized everything.** `Unknown` ranks
strictest, which is right for data — an unrecognized tag stays local — but the
same rank as a *ceiling* made it the most permissive one possible, because
every named class is below it. Federation maps any unrecognized policy string
to `Unknown`, so a single corrupt or newer-build row silently lifted the
publication bound to "publish Secret off-device".

## Broken on arrival

**Bundle export and import queried a table that has never existed.** Every
query in `bundles.rs` named a `session_events` table with `actor_json` /
`body_json` columns. The ledger is `events`, with `actor` / `body`, and no
migration in all 49 creates `session_events` — running the query against a
migrated database answers `no such table`. `ExportBundle` with transcripts,
`ImportBundle` and `MutateSessionLifecycle::Export` — three shipped, role-gated
commands — failed unconditionally. The column names were invented too, which is
what code written against an imagined schema and never once executed looks
like. `bundles.rs` had no tests; it now has an end-to-end one against a real
migrated database.

**A question could park its run forever.** `QuestionBroker::register_waiter`
overwrote a waiter that a reply had already pre-filled in the window between
the row committing and the waiter registering. The run then sat in
`WaitingForUserInput` indefinitely with the answer durably recorded and nothing
left to deliver it. `approvals.rs` fixed this exact race, and documented it,
without the fix reaching its mirror.

**Python LSP resolution had never worked on any machine.** The liveness probe
required `<binary> --version` to exit zero, which is not a question pyright
answers — it refuses every invocation that is not a live LSP connection. A
healthy install probed as a dead shim at both gates. Servers now record how
they can be *asked*, not just how they are spawned.

**The canary sample gate was defeated by the error class it exists to catch.**
The observation window was read outside any transaction and the store opened a
deferred one, so two concurrent or retried observations measured the identical
window and each added its samples — fifty real executions counted twice
satisfied a hundred. Now `BEGIN IMMEDIATE` plus a compare-and-swap on the
window.

**The web console's OAuth buttons started a sign-in nothing finished**, and
several other repairs: sync deltas acknowledged without being applied,
`write_file` destroying the file it was overwriting on a mid-write failure, an
audit-chain verifier reporting tampering on honest ledgers, a FIFO in the
worktree wedging a run, a UI worker killed every sixty seconds, and a
repository with more than 1000 lifetime pull requests never opening.

## Leaks, bounds and hot paths

- **Language servers leaked, one per run.** `LspManager` cached a client per
  (server, root) with no eviction and `LspClient::shutdown` had no callers, so
  every run left a server — rust-analyzer is hundreds of megabytes — holding a
  worktree that had been deleted. Reaped when the root vanishes, which is the
  one eviction trigger that needs no invented policy.
- **Desktop reconnect replay was O(n²).** Catch-up replays a session one frame
  per event and every one is a duplicate; answering "do I have this already?"
  rebuilt a map of the whole history and re-sorted it, per event. Now a binary
  search over the ordering invariant the module already enforces: **36 ms → 0
  ms** for a 400-event history, paid exactly when the operator had finished
  waiting out the backoff.
- `workspace.search` bounded matches but not bytes; the VS Code extension did a
  full inbox round trip per streamed token.

## Build and gates

**`cargo test --workspace` did not compile on macOS.** A test fixture used
rustix's `mknodat`, which is Linux-only — and `mkfifoat` is `cfg(not(apple))`,
so that crate offers no FIFO creation on macOS at all. Nothing caught it: the
macOS job ran one crate under a step named "Run macOS Sandbox and *Workspace*
Tests", and the full-workspace job runs on Linux. That job now compiles the
whole workspace's tests on macOS.

Three timing bounds were failing releases rather than finding bugs, and all
three are hang detectors that cost nothing when things are healthy: socket
reads 5 s → 30 s across eight suites, daemon startup waits 10 s → 60 s across
five, and the LSP liveness probe 500 ms → 2 s after it called a dead shim a
live server roughly one run in three under contention.
