# v0.12.3

A patch release of nothing but repairs. A full-workspace review — every CI
gate re-run, then five focused passes over the trust-boundary, server,
runtime, client and TypeScript surfaces — turned up sixteen defects. Each is
fixed here with a regression test that was run against the code it replaces
and confirmed to fail there, so every claim below is pinned by something that
would have caught it.

No behaviour anyone relies on changes. Two of these repairs make a feature
work that had never worked at all.

## Untrusted input that reached further than intended

**A tar entry could ship a setuid file into the runner's tree.** The
materializer exists to screen an untrusted archive, and then applied that
archive's file modes verbatim — `0o4755` produced a setuid file, setgid and
sticky came through the same way, and so did group- and world-writable bits,
in a tree the runner is about to execute from. The manifest path trusted its
mode just as literally, and a manifest travels with the archive. Modes are
now masked to owner-writable, group/other read-execute, which clears all of
that while preserving the only distinction anything downstream needs:
executable or not. A failed symlink creation in the same routine was
discarded with `let _ =`, leaving a tree missing a file the manifest promised
and every later check passing because nothing looks for what is not there.

**An Observer could get a signed write.** `presign_object_url` authorized
`Action::DownloadObject` regardless of the requested method, and
`DownloadObject` is granted to every role — so a read-only principal could
ask for a PUT presign and receive a signed write into the org's bucket
namespace, bypassing both `upload_object`'s Contributor gate and its
content-hash verification. The verb now picks the gate, and an unrecognized
verb is refused rather than mapped onto the weakest one.

**Webhook replay suppression could be walked past one re-casing at a time.**
The replay key was named `body-sha256` and hashed the signature *header*
string. `verify_signature` hex-decodes case-insensitively, so a captured
delivery re-verifies under any case permutation of its hex, and each
permutation minted a fresh fingerprint. It hashes the body now, as the key's
own name says.

**A secrets lease checked three of the five context axes it was minted
against.** Issuance binds principal, job, capability, organization and
repository; `resolve_lease` — where the material is actually handed over —
compared the first three and ignored the organization and repository it had
already selected onto the row. It is latent today, because the only
production issuer passes `None` for both, which is exactly how it would have
survived until something started passing them. Separately, `issue_lease`
resolved references by name only while every caller says id: the protocol
field is `SecretBind { reference_id }`, `secret list` prints the id first,
and the id was the one identifier that could never be bound. It accepts
either now, with an id match beating a name match.

## Writes that could half-happen

**A sync delta could be acknowledged without being applied.** `accept_delta`
wrote three autocommits in a row — receipt, projection, stream event. A
failure after the first left a durable receipt for an effect that never
happened; the daemon's retry then hit the duplicate short-circuit, was handed
that receipt, and marked its outbox entry acknowledged. The delta was gone
and neither side reported a loss. The three writes are one unit of work now,
with the duplicate check inside the transaction, which also closes a race
between two concurrent deliveries of one sequence. Publication stays after
the commit: a crash between commit and broadcast leaves the event durable and
readable, where the reverse would announce an effect that never existed.

**Revoking a publisher could stop halfway.** Four dependent writes, each its
own autocommit, and the partial states between them are the dangerous kind —
a failure after the first leaves the publisher marked revoked while every
install of their packages stays enabled, with no path that ever goes back to
finish. Revocation is precisely the operation that must not be half-done. One
transaction now.

**`write_file` destroyed the file it was overwriting if anything went wrong
mid-write.** `set_len(0)` + `write_all` loses the user's data to a full disk,
an I/O error or a killed daemon — which is `secure_fs::replace_contents`' own
documentation, written when `edit_file` was hardened against exactly this.
`write_file` kept doing the condemned thing with the same handle in scope. It
publishes by rename now, pinned with the same hard-link witness test.

**The audit-chain verifier reported tampering on honest ledgers.** It
re-sorted records by `occurredAt` before checking them; timestamps are not
unique, `sort` is stable, and records sharing a timestamp kept arrival order.
When that was not chain order, the `prevHash` check failed and the verifier
cried tamper. That is the expensive direction to be wrong in — a tamper
verdict is the one result a reader cannot afford to learn to ignore. The
chain links are the real ordering, so they are what it follows now;
timestamps survive only as a deterministic tiebreak, and records unreachable
from any beginning are still judged rather than silently passed over.

## Runs that could stop and not come back

**A FIFO in the worktree wedged the run.** `secure_fs` refuses anything that
is not a regular file, but that check reads metadata from a descriptor, so it
cannot run until `openat` has returned — and on a FIFO the open *is* the
blocking call, unbounded in both directions. A `mkfifo` dropped in by any
allowed build command hung `read_file`/`write_file`/`edit_file` for the life
of the process, past a step wall clock that is only consulted between steps.
The leaf is opened `O_NONBLOCK` now, fstat'd, and the flag cleared — so the
open returns either a descriptor or `ENXIO` and the existing refusal gets to
run either way.

**A UI worker was killed every sixty seconds.** The native-process arm sets
an explicit 24-hour wall clock and explains why; the ui-component arm derived
its profile from the manifest, and `ResourcesSpec` is `#[serde(default)]`, so
a manifest without a `[resources]` block — which is most of them — inherited
the 60-second default meant for a short plugin script. The worker was killed,
tripped the circuit breaker, backed off, restarted, and did it again for as
long as it stayed enabled. Both arms name the same constant now, and a
declared cap still stands.

**A repository with more than 1000 lifetime pull requests could never open
another one.** The page bound was treated as a correctness boundary: reaching
it refused the whole operation, so on a mature repo `create_draft_pull_request`
failed deterministically and permanently, with the bound receding further
every time a PR merged. The scan stops at the bound and warns now, and asks
for newest-first explicitly, since a bounded window's value is entirely in
which end of history it covers. In the other direction, the duplicate match
required `pr.state == "open"` directly beneath a comment explaining that it
must not — so closing a marked PR made its marker invisible and the next call
created a duplicate, the exact failure the scan exists to prevent.

**A rate-limited native provider was retried on the generic schedule.** The
OpenAI-compatible client reads `Retry-After` and embeds the hint that
`codypendent_providers::retry` parses back out; the native client — same
file, same helper in scope — ignored it, so a server that had just said "not
yet" and named a time got hammered anyway.

## Features that were dead

**Python LSP resolution had never worked on any machine.** The liveness probe
ran `<binary> --version` and required exit 0. That is not a question pyright
answers: `pyright-langserver` refuses every invocation that is not a live LSP
connection, exiting 1 with "Connection input stream is not set". So a
perfectly healthy install probed as a dead shim, at both gates —
`ScriptAdapter::capability` answered `SyntaxOnly` and `LspManager::client_for`
refused to spawn. The roster already knew how each server is spawned; it now
also records how each one can be *asked*. Four servers keep the `--version`
probe; pyright gets proved the way the manager will actually use it — spawned
with its real arguments, stdin held open as a pipe, required to still be
running a moment later, with its process group swept on the way out because
the wrapper script spawns node. Verified against a real uv-installed
`pyright-langserver`: the old probe answers false, the new one true, and
capability moves `SyntaxOnly → LspResolved`.

**The web console's OAuth buttons started a sign-in nothing finished.** The
GitHub and OIDC buttons sent the browser to the provider and nothing in
`apps/web` ever consumed the redirect — `handleCallback` and
`handleOAuthCallback` had zero callers, so no token was installed and no
session created. The only sign-in that worked was pasting a bearer token by
hand, and only until the page reloaded, because nothing persisted it either.
The app reads the redirect on load now and shows a "completing sign-in"
screen while it exchanges the code; a provider refusal or a failed exchange
surfaces its reason. The single-use code is stripped from the address bar
*before* the exchange is awaited, so a reload or StrictMode's double-invoke
cannot present a spent code and turn a success into a failure. Persistence
watches the token rather than the act of setting it, which is what covers the
rotated token whose loss is a silent sign-out; it lives in `sessionStorage`,
so a reload keeps you signed in but the token never reaches disk.

## Bounds that were missing

**`workspace.search` bounded matches but not bytes.** An `rg --json` match
event embeds the entire matched physical line, and every sibling tool bounds
its capture — shell at 16 MiB, `read_file` at 64 MiB, the salient view at
2048 bytes a line — while this one bounded nothing. One minified bundle in
the tree was read whole into a `String`, and up to 200 such lines rendered
into a transcript that is re-sent to the model every step until compaction: a
single search could blow the context by itself. Two bounds now, because one
does not do it — the stream is read through `Take` at 16 MiB, since
`next_line` buffers a whole line before any code here can inspect it, and
each kept line is clamped to 2048 bytes.

**The VS Code extension did a full inbox round trip per streamed token.** The
`event` handler called `refreshInbox()` unconditionally, and a streaming
reply is tens of deltas a second, so the list was refetched constantly to
redraw something that had not changed. It now asks the two predicates that
already decide whether an event raised or resolved blocking work — the same
ones the notifier uses, so the gate cannot drift beside it. Those refreshes
also raced: two overlapping reads settled in whatever order the daemon
answered, so a slower one could paint a resolved approval back over a fresh
list, where it looks like an approval that will not go away. A monotonic
ticket drops stale responses. In the SDK, `SessionStore` appended every event
forever and copied the whole array each time — quadratic in session length,
on the hot path of a live stream. Snapshots retain a bounded tail of the
newest 2000 events, and the truncation is never silent: a `droppedEvents`
count says how much fell off the front.

## Build and gates

The `cfg(not(unix))` fallback for `open_resolved_path` took `&PathBuf` while
its caller passes `&Path` and the module imports only `Path`, so any non-Unix
build of the workspace core failed to compile — twice, on a function whose
whole purpose is to be the portable arm. Verified by forcing the fallback
live on a Linux build.

Three test failures that appeared only in root containers or beside a real
pyright install are fixed at the test, not the product: mode bits do not bind
uid 0, so a `0o500` directory genuinely is writable for root and two probes
were asserting a falsehood there. `ci` installs ripgrep from a pinned tarball
rather than apt, after an untimed mirror stall. The doc-count markers in
`ROADMAP.md` are re-settled against this branch's new tests — 3819 static
`#[test]` attributes, 298 VS Code vitest tests from a real reporter run.

## Verified

`cargo fmt` across all three workspaces, `cargo clippy --workspace
--all-targets --all-features -- -D warnings`, and `cargo test --workspace
--all-features` at 3830 passing across 158 binaries. All eight Node packages
green on typecheck, lint, test, build and `npm audit --audit-level=high`. The
two transaction repairs were verified against a live PostgreSQL 16, failing
on the old ordering and passing on the new.

One finding from the review is deliberately **not** in this release: the
daemon's control-plane sync client and the server disagree on the wire shapes
for push and pull. Repairing it needs the daemon to persist the `daemon_id`
that pairing already returns and discards — a schema migration — and a notion
of which repositories a daemon subscribes to, which does not exist anywhere
yet. That is a design decision, not a patch, and the path stays latent until
the background loop is started in production.
