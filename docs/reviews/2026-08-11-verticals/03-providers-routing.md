# Agent report: Providers / model selection / routing

## How model selection works today (traced, file:line)

**Catalog layer.** `crates/providers/builtin_catalog.toml` embeds 42 providers (Nebius at :192-199) — id, protocol, base_url, auth env-var names. It contains **zero `[[model]]` rows**. Parsed at build time (`crates/providers/src/catalog.rs:10,32-44`); a user `<data_dir>/providers.toml` shadows/extends by id (`catalog.rs:82-109`). The `Model` metadata schema exists (`crates/providers/src/model.rs:119-131`: name, context_tokens, cost_per_1m input/output) and `Catalog::model()/models()/builtin_models()` exist (`catalog.rs:39-44,124-131`), but **no code outside the providers crate calls any of them** (verified by grep) — the metadata seam is fully shaped and completely unconsumed.

**TUI browse.** The CLI harness seeds `/provider` picker cards via `load_provider_cards` (`crates/cli/src/tui.rs:3567-3679`): protocol/auth labels, `requires_key` (:3688), `can_list_models` (:3700 — OpenAiChat + non-blank base_url + first auth ApiKey/None), `available` = `provider_runtime_supported` (:3713, aliased to `can_list_models`). Catalog ACP rows are replaced by the live ACP registry (:3586, :3627-3654). Unavailable providers (Anthropic-native, Gemini-native, cloud-IAM, OAuth) render but Enter refuses with "catalog-only" (`crates/tui/src/reduce.rs:2840-2848`).

**Add-model with live discovery.** Enter/Tab on a provider → `enter_add_model_flow` (`reduce.rs:2824-2839`): hosted+listable → masked key-first prompt `Overlay::AddModelProviderKey`; local+listable → immediate query; non-listable → free-text `AddModelId` (`crates/tui/src/state.rs:272-315`). The reducer emits client-only `Intent::QueryProviderModels`; the harness drain loop intercepts it (`crates/cli/src/tui.rs:1438-1478`), resolves the catalog base_url + auth header/prefix, and spawns `query_provider_models` (:2910-2951): **GET `{base_url}/models`** (`models_url` :2865-2867, sibling of the versioned base — never `/v1/models`), 10s timeout, key marked `set_sensitive` (:2925-2928), key-free error strings. Response parsed defensively (:2875-2900, `{data:[{id}]}`, dedup, empty→Err). Result flows back as `ReaderSignal::ProviderModels` → `Action::ProviderModelsLoaded/Failed` (:1202-1205) → `Overlay::AddModelPick` (filterable bare-string list) or free-text fallback carrying the key. **No caching — fetched per add** (spec constraint, `docs/superpowers/specs/2026-07-26-model-discovery-design.md:383`). No key: local/no-auth providers query keyless; a 401 just falls back to free-text.

**Persistence.** Pick → `Intent::AddModel` → `write_add_model` (`cli/src/tui.rs:2480-2604`): appends/updates a `[[model]]` in `<data_dir>/models.toml` (`provider = "openai-compatible"`, base_url from catalog, `api_key_env = ""`, `context_tokens: None` :2569-2576) and writes the key to `auth.json` mode 0600, atomically, all-or-nothing (:2504-2516). Picker re-seeds immediately (`apply_add_model` :2638-2656) — no daemon restart.

**Selection/pinning.** `/model` picker cards come from `load_model_cards` (:3428-3505): models.toml joined with measured `model_profiles` rows for location/cost/context badges (`model_card` :3519-3556); readiness = ACP launch-spec check, live `check_model` for local endpoints, **`Unverified` for hosted** (:3499-3500, deliberately no key burn). Enter stages `pending_model` (`reduce.rs:2799-2815`, blocks `Unavailable` rows), which rides `StartRun.model`/`SubmitUserInput.model` (:2932, :2941; protocol `crates/protocol/src/command.rs:122-160`).

**Daemon execution.** `executor.rs:568-655`: pinned model → `routing.validate_pin` (security-only check) + `registry.check_model`; no pin → `routing.select` (default OFF) else Phase-1 `resolve_model`. `check_model` (`crates/runtime/src/models.rs:330-412`) GETs `/models` and requires the configured id to be listed; `client_for` (:436-465) builds only an `OpenAIChatCompletionClient`; key precedence auth.json → env → none (:304-325).

## Verified working

- **Live `/models` discovery** end-to-end, with correct URL construction, timeout bounding, race-guarded overlay fold, and free-text fallback that never re-prompts the key (`cli/src/tui.rs:2865-2951`, `reduce.rs` handlers per plan; unit tests at `cli/src/tui.rs:6481-6541`).
- **Secret hygiene**: `SecretKey` redacting Debug, masked render, 0600 `auth.json`, key never in an `Action`/reason; `ResolvedCredential` Debug redaction (`crates/providers/src/credential.rs:29-41,149-162`).
- **Model-profile store** (0014 + `crates/daemon/src/model_profiles.rs`): authoritative `profile_json` with derived scalar columns (:63-101), per-(model,endpoint) keying, capability-probe cache (:149-194), thorough round-trip tests.
- **Routing engine** (`crates/routing`): security-before-utility hard filters (`router.rs:309-338`), utility scoring (:422-434), cycle-proof escalation (:232-273), validated policies rejected at deserialization (`policy.rs:93-145`), hosted-$0 "unmeasured price" honesty (`router.rs:320-327`).
- **Routing seam wired live**: `RoutingCoordinator.select`/`validate_pin` run in the executor per run (`executor.rs:586-628`), fail-closed on refusal/no-profiles/garbage `routing.toml` (`codypendentd/src/routing.rs:145-188,207-228`), decisions recorded as trace notes (:513-521). Excellent leak tests (:1014-1099).
- **`codypendent models bench`** persists measured `LocalBench` profiles (`cli/src/commands.rs:2579-2650`).
- **Phase-1 fallback resolution** with per-candidate `/models` verification and structured all-failed errors (`runtime/src/models.rs:627-685`).

## Bugs & broken wiring (severity)

1. **HIGH — auth header/prefix and extra_headers are dropped when a model is added.** `write_add_model` flattens every provider to `provider = "openai-compatible"` with no header info (`cli/src/tui.rs:2550-2556`); `ModelConfig` has no header/prefix/extra_headers fields (`runtime/src/models.rs:63-90`); `config_to_protocol_auth` hardcodes `Authorization`/`Bearer ` (:287-295) and `check_model` uses `bearer_auth` (:371-373). Azure OpenAI (catalog `header = "api-key"`, `builtin_catalog.toml:100-108`) and GitHub Models (`extra_headers` :305) pass `provider_runtime_supported` and even **list models correctly** (discovery uses the catalog header, `cli/src/tui.rs:1450-1455`) — then the added model authenticates with the wrong header at run time. Silent success in the add flow, guaranteed 401 in the run.
2. **MED — catalog `[[model]]` metadata is dead code.** Even a user who hand-writes `[[model]]` rows into providers.toml gets nothing: no consumer of `Catalog::models()` exists outside the crate. Rubric #3's "prefilled model lists" has a landing zone but no runway.
3. **MED — `provider-anthropic` is a phantom feature.** `agent-framework-anthropic` is pinned (`runtime/Cargo.toml:36,61`; root `Cargo.toml:59`) but `agent_framework_anthropic` appears in zero `.rs` files. `Protocol::Anthropic` always returns `ProtocolNotWired` (`models.rs:460-464`). Honestly gated in the UI, but the dependency suggests wiring that never happened.
4. **LOW/MED — `requires_key` mis-derived on discovery fallback.** `ProviderModelsFailed` sets `requires_key: api_key.is_some()` (doc'd at `state.rs:266-270`). A hosted provider + blank key at the key-first prompt + failed query → fallback with `requires_key: false` → a keyless model is written and 401s later, instead of routing through `AddModelKey`.
5. **LOW — added models get `context_tokens: None`** (`cli/src/tui.rs:2575`), so no `num_ctx` hint and no TUI context-percentage for every discovered model, even when the provider's `/models` response (e.g. OpenRouter's `context_length`) carried it — `parse_models_response` discards all fields but `id` (:2888-2895).
6. **LOW — trailing-slash base_urls** (`nebius` :196 `…/v1/`, `gemini` :30) are stored verbatim; `models_url` trims but the chat client's join behavior is the framework's — possible `//chat/completions`.
7. **LOW — hosted readiness is never verifiable on demand**: cards stay `Unverified` (:3499-3500) with no "test this model" action, so the first signal of a bad key is a failed run (mitigated by `/keys` status view and `check_model` at run start).

## Gaps vs rubric #3 (with plug-in points)

- **No prefilled model lists.** Exact plug-in: (a) populate `crates/providers/builtin_catalog.toml` with `[[model]]` rows (schema ready, `model.rs:119-131`) for Nebius, OpenAI, Groq, DeepSeek, etc.; (b) in the harness drain arm for `QueryProviderModels` (`cli/src/tui.rs:1438-1478`), seed `Catalog::models()` filtered by `provider_id` as instant results and/or as the fallback instead of free-text on GET failure; (c) extend `Overlay::AddModelPick` from `Vec<String>` (`state.rs:309-315`) to a card row so `render_add_model_pick` (`render.rs:5230+`) can show name/context/price from `Catalog::model()`.
- **No per-model capability metadata anywhere.** The catalog `Model` lacks tools/vision/reasoning flags; `ModelCapabilities` (`routing/src/capability.rs:55-67`) only materializes after a bench/probe. Add capability fields to the catalog `Model` and map them into badges plus a default `ModelCapabilities` for routing profiles.
- **Selection is not "easy" yet**: substring-only filtering (`filter_model_names`, `state.rs:942-950`), no fuzzy match, no favorites/recents/grouping, no recommended-default per provider, no price display in the pick-list — all specified in `docs/architecture/model-provider-selection.md:83-98` but unbuilt.
- **No discovery cache/refresh** (explicit non-goal, design :383): each add re-fetches; existing providers' lists can't be re-browsed or models removed (no manage view).
- **`context_tokens` auto-population** from catalog or `/models` response is explicitly "not in v1" (`runtime/src/models.rs:81-90`).
- **Nebius specifically**: reachable today only via typing after a successful live list (works, since Nebius is OpenAI-compatible), with zero pricing/context metadata shown.

## Routing layer: real vs aspirational

**Real:** the engine (filters, utility, escalation, policy validation, classifier) is complete and heavily tested; the daemon seam (`codypendentd/src/routing.rs`) is wired into the live executor for both routed selection and pin validation (`executor.rs:586-628`); `eval run --policy` routes eval cases through the real `Router` over persisted profiles (`cli/src/eval.rs:243-261`); capability probes cache per model+endpoint and override declarations (`routing.rs:573-647`); profiles are endpoint-bound and location-revalidated (:577-592).

**Aspirational:** (1) **Escalation is never live-driven** — `RoutingCoordinator::escalate`/`record_transition` are `#[cfg_attr(not(test), allow(dead_code))]` (:485-486, :526), blocked on a mid-run model-switch hook ("would emit a second terminal `RunCompleted`", :477-484). (2) **`arms.rs` has zero consumers** outside the routing crate — these are *static comparison arms* for an eval gate, not learning bandits (no reward updates/sampling anywhere); the promised `codypendent eval route --suite core` command does not exist (`cli/src/main.rs:544-545,931` — `models bench` is the only `models` subcommand; no `eval route`). (3) Routing is default-OFF behind a hand-written `routing.toml`, and profiles only exist for models an operator benched — hosted models additionally need a hand-set real price to be eligible at all (`router.rs:320-327`), so in practice the router governs almost nothing today. (4) Per-run data classification is always `None` (`executor.rs:592-595,621-625`) — the config ceiling (fail-closed `Unknown`) does all the work. (5) The capability prober trait exists but no production prober is injected (`routing.rs:327-335`).

## Prioritized opportunities (S/M/L, impact)

1. **S, very high:** Ship curated `[[model]]` rows in `builtin_catalog.toml` (top ~15 providers, incl. Nebius) + pre-fill/fallback in `AddModelPick`. Turns discovery-failure dead-ends into a working picker offline and gives price/context columns for free.
2. **S, high:** Carry `context_tokens` (from catalog row or a richer `/models` parse) into `write_add_model` (:2575) — fixes context UX and routing size-filter inputs for every added model.
3. **M, high (correctness):** Persist auth header/prefix + extra_headers per model (extend `ModelConfig`, or store `provider_id` and re-resolve from the catalog in `client_for`/`check_model`) — unbreaks Azure/GitHub Models; today these fail only after a seemingly successful add.
4. **M, high:** Upgrade `AddModelPick` to metadata cards (name, ctx, $/1M in/out, capability badges, "recommended" pin) + fuzzy filter shared with the model picker; add favorites/recents per the architecture doc.
5. **M, medium:** Cache discovery results per provider (`<data_dir>/model_lists/<provider>.json`, TTL + manual refresh), enabling a browse-without-adding view and offline re-picks.
6. **M, medium:** Wire `Protocol::Anthropic` through the already-pinned `agent-framework-anthropic` (the `client_for` dispatch point at `models.rs:444-464` is exactly shaped for it).
7. **L, medium:** Live cascade escalation — the mid-run model-switch hook in `FrameworkAgentRuntime`, then flip `escalate` out of test-only; add the five-arm `eval route` CLI to make `arms.rs` real.
8. **S, low:** CLI parity — `codypendent models list/add/check` (today only `bench` exists), so headless users aren't forced into hand-editing.

## Extra ideas

- **Free metadata from richer `/models` responses:** OpenRouter/Nebius return `context_length`/pricing in the same endpoint you already call — extend `parse_models_response` to keep optional fields instead of discarding them (:2876-2895), and upsert them as display metadata (and even seed hosted `model_profiles` prices, unlocking routing eligibility for hosted models without hand-editing).
- **Auto-profile on add:** after `write_add_model`, offer "bench now" for local models (populating routing profiles) and a one-shot cheap ping for hosted keys, upgrading `Unverified` to a real status.
- **models.dev import:** the architecture doc names it (`model-provider-selection.md:64-66`); a vendored snapshot converted to `[[model]]` rows would give breadth without a network dependency, matching the "no live catalogue in v1" constraint.
- **Classification badges in the picker** — the differentiator the design doc claims (:141-146) is fully buildable today: `ModelCard.location` already exists; adding the active `RoutingPolicy` ceiling to the picker header closes the loop.
- **Key-per-provider option** in `auth.json` (noted open question in `2026-07-24-tui-add-model-design.md:136-139`) — adding three Nebius models currently means entering the same key three times.
