# Codypendent UX review — 2026-09-01

A usability review of every surface a person touches — the Ratatui TUI, the
Tauri desktop app, the CLI, and the model/agent connection path they all share —
with the fixes that shipped from it and the gaps that remain.

Baseline: `main` at v0.14.0 (`f47c2d4`). Method: three specialist read-throughs
(TUI, desktop, provider plumbing) against the code and the earlier reviews,
followed by implementation on `claude/codypendent-ui-ux-review-6r5zaw`. Every
finding below names a file; every fix names its commit. Findings marked
**open** were not implemented in this pass and say why.

## The short version

The product's best surface is the TUI, and its worst moments were where the
two clients met the daemon and the models: nothing told a first-time desktop
user that a daemon had to be started; a parked question could be notified but
not answered; a failed run rendered as dim grey text with the raw provider
error (credential included); a rate-limited run looked like a hang in every
client; and the TUI's failure-recovery keys, printed under every failed run,
did nothing from the normal view. Those are all fixed. What remains open is
architectural: model failures still cross the wire as an unstructured string,
and the desktop's four knowledge views still have no data source.

## What shipped

### Desktop (`apps/desktop`)

Commit `80437f8` — run feedback:

- `ModelRetrying`, `ToolDenied`, `BudgetWarning` and `RunUsage` were dropped
  by the store's default arm. A provider backoff now shows the daemon's reason
  and countdown in the composer strip and the transcript; a policy denial and
  a budget warning are rows; usage renders as `1,234 in · 567 out · $0.0034`
  with an unmeasured dimension absent rather than zero.
- The store derives a run activity from the newest event, and the transcript
  draws a pulsing working row between visible updates, so a cold provider's
  first ten seconds are no longer indistinguishable from a hang.
- A `Failed` disposition is a failure card: reason sanitised (`failure.ts`, a
  port of the TUI's sanitiser and summariser), a hint naming the next step,
  buttons for it (Open API keys, Choose a model, Retry with the same
  objective), the full chain folded underneath.
- The composer keeps the draft until the daemon accepts the run; the model
  half of the status strip stays visible while a run is live and is labelled
  as the next run's staging.
- `theme.css`: semantic colour tokens (dark and light), a visible keyboard
  focus ring, and `prefers-reduced-motion`.

Commit `506ad2f` — the daemon, questions, readiness:

- `launcher.rs`: the shell finds `codypendent` (or `codypendentd`) on `PATH`,
  in the installer's directories, beside the app, or via `CODYPENDENT_BINARY`,
  starts it detached with output in the daemon log, and waits for the socket.
  The connection banner explains what is missing, offers Start daemon and
  Retry now, and names `codypendent daemon start` when it cannot. A version
  footer shows daemon, protocol and desktop versions and calls out a mismatch.
- A question card offers the prompt's options, a typed answer where allowed,
  and a rejection with feedback, through a new `resolve_question` command.
  Before this the run stayed blocked until someone opened the TUI.
- Models shows the TUI's readiness badge for every configured model and a
  per-row Test that asks the provider; the staged mode and model persist
  across launches; notices distinguish success from failure; Providers tells
  a user looking for Claude Code or Codex which CLI commands add them; the
  four knowledge views the shell cannot serve are badged in the sidebar and
  palette.

### TUI (`crates/tui`, `crates/cli/src/tui.rs`)

Commit `c9af7d2`:

- Failure-card chips (Alt-R/A/M/D) work from the normal view and say so
  when there is nothing to act on (`reduce.rs::failed_run_context`).
- `q` closes the open view; Ctrl-C detaches (`input.rs::map_normal_char`).
- Guided setup opens from an empty Enter whenever no model can run, and from
  `/setup` in the palette (`reduce.rs`, `palette.rs`).
- Only a word-initial `@` mentions a file; Enter with no match sends
  (`reduce.rs::check_mention_popup`, `mention_select`).
- A persistent `Connection lost · reconnecting…` status row with a seconds
  counter, and `reconnecting` in the telemetry health field
  (`state.rs::Link`, `render.rs::render_status_line`).
- The retry reason and delay from `ModelRetrying` reach the activity row in
  both the graphical and accessible clients.
- Failure summaries recognise authentication, rate-limit and network failures
  and the Alt-A hint uses the same test (`render.rs::summarize_error`).
- The "Checking model" wait has a spinner, redraws every tick, and times out
  after 45 s; the reason a connection attempt failed is shown in the provider
  picker's detail pane (`OnboardFlow::error`).
- Onboarding provider rows tick only when a key is in hand; the provider
  picker's hints get their own row; header and telemetry agree on the model;
  Esc-Esc with nothing to rewind says so; the splash shows a warning glyph and
  "connect a model" when no model can run; Ctrl-T verifies from the model
  picker; the help overlay lists the recovery keys, Ctrl-Z, `@` and `q`;
  Alt+Enter is spelled as the docs spell it; empty browsers name their fill
  path; prices print with four decimals; the Unsloth loading box has a spinner.

### Provider plumbing (`crates/runtime`, `crates/cli`, `crates/codypendentd`)

- Native (Anthropic/Gemini) HTTP errors are classified like the
  OpenAI-compatible path, so a 401 is an authentication failure everywhere
  (`runtime/src/models.rs`).
- `AllCandidatesFailed` prints `id: reason` per candidate instead of a Rust
  tuple vector.
- `models add` on an existing id keeps a hand-set `api_key_env` and
  `context_tokens` (MEGAPLAN R-COR-3).
- `doctor` reports a hosted model with no resolvable credential as a failure
  without `--deep`, using the network-free check.
- `models list` and the TUI's `/keys` consult the catalog's documented
  environment variable names, so a working `OPENAI_API_KEY` no longer reads
  as `key: none` (2026-08-13 review A9).
- The daemon's model registry layers `providers.toml`, so a user-defined
  provider authenticates at run time the way `models check` said it would.
- `write_remove_model` uses a per-write temp name (MEGAPLAN R-COR-2 residue).

### CLI, web, VS Code

Not the focus of this pass. Two things worth recording: the web app
(`apps/web`) is a control-plane console, not a run surface, and its
`index.css` already uses tokens; the VS Code extension has no model surface at
all and inherits every daemon-side improvement above. `models add` already
points an ACP provider at `codypendent acp connect`.

## What to do next

In order of value for the effort:

1. **Structured failure on the wire (P2).** Add `#[serde(default)] error:
   Option<CodypendentError>` beside `RunDisposition::Failed.reason`, populate
   `user_action` from the framework's typed `ServiceInvalidAuth` and the
   `ModelsError` variants, and let both clients' failure cards read the field
   before falling back to text. Golden vectors and the generated TS follow.
2. **Register the four knowledge commands in the desktop shell (D8).**
   `ListUiPlugins`, `InspectMemory`/`CorrectMemory`/`ForgetMemory` and the
   document commands exist on the wire; skills need the registry read the TUI
   harness already does.
3. **Local endpoint autodetection (P12)** in the TUI's onboarding lane and in
   `doctor`.
4. **`ProbeModel` on the protocol (P10)**, so every client shares one probe.

Done since the list was first written: focus management and the Back
affordance (D17, D18, D21, `310f027`) and the token migration (D19).
