# Codypendent UX review — 2026-09-01

A usability review of every surface a person touches — the Ratatui TUI, the
Tauri desktop app, the CLI, and the model/agent connection path they all share —
with the fixes that shipped from it and the gaps that remain.

Baseline: `main` at v0.14.0 (`f47c2d4`). Method: three specialist read-throughs
(TUI, desktop, provider plumbing) against the code and the earlier reviews,
followed by implementation on `claude/codypendent-ui-ux-review-6r5zaw`. Every
finding below names a file; every fix names its commit. Findings marked
**open** were not implemented in this pass and say why.

## The short version

The product's best surface is the TUI, and its worst moments were where the
two clients met the daemon and the models: nothing told a first-time desktop
user that a daemon had to be started; a parked question could be notified but
not answered; a failed run rendered as dim grey text with the raw provider
error (credential included); a rate-limited run looked like a hang in every
client; and the TUI's failure-recovery keys, printed under every failed run,
did nothing from the normal view. Those are all fixed, and so are the two
architectural gaps this review first recorded as open: a failed run now carries
its classified cause on the wire, and the desktop's four knowledge views read
the daemon's database as the TUI does. What remains open is listed under
Findings, and none of it blocks a first run.

## What shipped

### Desktop (`apps/desktop`)

Commit `80437f8` — run feedback:

- `ModelRetrying`, `ToolDenied`, `BudgetWarning` and `RunUsage` were dropped
  by the store's default arm. A provider backoff now shows the daemon's reason
  and countdown in the composer strip and the transcript; a policy denial and
  a budget warning are rows; usage renders as `1,234 in · 567 out · $0.0034`
  with an unmeasured dimension absent rather than zero.
- The store derives a run activity from the newest event, and the transcript
  draws a pulsing working row between visible updates, so a cold provider's
  first ten seconds are no longer indistinguishable from a hang.
- A `Failed` disposition is a failure card: reason sanitised (`failure.ts`, a
  port of the TUI's sanitiser and summariser), a hint naming the next step,
  buttons for it (Open API keys, Choose a model, Retry with the same
  objective), the full chain folded underneath.
- The composer keeps the draft until the daemon accepts the run; the model
  half of the status strip stays visible while a run is live and is labelled
  as the next run's staging.
- `theme.css`: semantic colour tokens (dark and light), a visible keyboard
  focus ring, and `prefers-reduced-motion`.

Commit `506ad2f` — the daemon, questions, readiness:

- `launcher.rs`: the shell finds `codypendent` (or `codypendentd`) on `PATH`,
  in the installer's directories, beside the app, or via `CODYPENDENT_BINARY`,
  starts it detached with output in the daemon log, and waits for the socket.
  The connection banner explains what is missing, offers Start daemon and
  Retry now, and names `codypendent daemon start` when it cannot. A version
  footer shows daemon, protocol and desktop versions and calls out a mismatch.
- A question card offers the prompt's options, a typed answer where allowed,
  and a rejection with feedback, through a new `resolve_question` command.
  Before this the run stayed blocked until someone opened the TUI.
- Models shows the TUI's readiness badge for every configured model and a
  per-row Test that asks the provider; the staged mode and model persist
  across launches; notices distinguish success from failure; Providers tells
  a user looking for Claude Code or Codex which CLI commands add them; the
  four knowledge views the shell cannot serve are badged in the sidebar and
  palette.

### TUI (`crates/tui`, `crates/cli/src/tui.rs`)

Commit `c9af7d2`:

- Failure-card chips (Alt-R/A/M/D) work from the normal view and say so
  when there is nothing to act on (`reduce.rs::failed_run_context`).
- `q` closes the open view; Ctrl-C detaches (`input.rs::map_normal_char`).
- Guided setup opens from an empty Enter whenever no model can run, and from
  `/setup` in the palette (`reduce.rs`, `palette.rs`).
- Only a word-initial `@` mentions a file; Enter with no match sends
  (`reduce.rs::check_mention_popup`, `mention_select`).
- A persistent `Connection lost · reconnecting…` status row with a seconds
  counter, and `reconnecting` in the telemetry health field
  (`state.rs::Link`, `render.rs::render_status_line`).
- The retry reason and delay from `ModelRetrying` reach the activity row in
  both the graphical and accessible clients.
- Failure summaries recognise authentication, rate-limit and network failures
  and the Alt-A hint uses the same test (`render.rs::summarize_error`).
- The "Checking model" wait has a spinner, redraws every tick, and times out
  after 45 s; the reason a connection attempt failed is shown in the provider
  picker's detail pane (`OnboardFlow::error`).
- Onboarding provider rows tick only when a key is in hand; the provider
  picker's hints get their own row; header and telemetry agree on the model;
  Esc-Esc with nothing to rewind says so; the splash shows a warning glyph and
  "connect a model" when no model can run; Ctrl-T verifies from the model
  picker; the help overlay lists the recovery keys, Ctrl-Z, `@` and `q`;
  Alt+Enter is spelled as the docs spell it; empty browsers name their fill
  path; prices print with four decimals; the Unsloth loading box has a spinner.

### Provider plumbing (`crates/runtime`, `crates/cli`, `crates/codypendentd`)

- Native (Anthropic/Gemini) HTTP errors are classified like the
  OpenAI-compatible path, so a 401 is an authentication failure everywhere
  (`runtime/src/models.rs`).
- `AllCandidatesFailed` prints `id: reason` per candidate instead of a Rust
  tuple vector.
- `models add` on an existing id keeps a hand-set `api_key_env` and
  `context_tokens` (MEGAPLAN R-COR-3).
- `doctor` reports a hosted model with no resolvable credential as a failure
  without `--deep`, using the network-free check.
- `models list` and the TUI's `/keys` consult the catalog's documented
  environment variable names, so a working `OPENAI_API_KEY` no longer reads
  as `key: none` (2026-08-13 review A9).
- The daemon's model registry layers `providers.toml`, so a user-defined
  provider authenticates at run time the way `models check` said it would.
- `write_remove_model` uses a per-write temp name (MEGAPLAN R-COR-2 residue).

## What to do next

In order of value for the effort:

1. **Migrate the in-process probes onto `ProbeModel`** — the TUI's picker,
   `models check`, and the desktop's Models page each still build their own
   `ModelRegistry`. The wire command that replaces them now exists (P10); this
   is the client half, and it is what lets the desktop shell stop linking
   `codypendent-runtime`'s `provider-openai` feature.
2. **`ModelSelected` on the wire (P11)**, so a routing decision is a fact a
   client can render rather than a free-text note.
3. **A shared models-file crate (P13)**, so the desktop's `models.toml` writers
   stop being a hand copy of `models_file.rs`.
4. **The active model in `SessionProjection` (P14)**, so a catch-up client can
   show it without replaying the whole ledger.

Done since the list was first written: focus management and the Back
affordance (D17, D18, D21, `310f027`), the token migration (D19, `8c6867f`),
and the desktop's knowledge surfaces (D8): the shell now serves Skills,
Memory, Docs and Plugins, reading the daemon's database exactly as the TUI
harness does and sending the daemon-owned mutations over the live connection.
Local endpoint autodetection (P12) followed: setup and `doctor` now say which
of Ollama, LM Studio and vLLM is actually answering. And the structured
failure (P2) is on the wire: a failed run carries its classified cause, so a
client offers the right affordance without reading the message.

## Validation

- `cargo test -p codypendent-tui` (729 unit + 5 VT100 snapshot tests, three
  snapshots updated for the new chip label and the longer help table),
  `cargo test -p codypendent-cli --lib`, `-p codypendent-runtime --lib`,
  `-p codypendent-codypendentd --lib`; `cargo clippy --all-targets -- -D
  warnings` and `cargo fmt --check` on every touched crate.
- Desktop: `tsc --noEmit`, `vitest` (205 tests across 35 files, 47 new), `vite
  build`; the Tauri workspace's `cargo test` (47), `clippy -D warnings` and
  `fmt --check`, with the Linux webkit dependencies installed as CI's
  `desktop-tauri` job does.
- Protocol: golden vectors regenerated (`RunDisposition_Failed_with_error`
  added), schemas exported and the TypeScript bindings regenerated;
  `cargo test -p codypendent-protocol --all-features`, `sdk/protocol`'s
  `npm run check` (drift gate, typecheck, 462 vector tests, build), and the
  VS Code extension's vector suite (151) and `tsc --noEmit`.
- Review follow-ups (the four defects the PR's review bots found, each with a
  test that fails without its fix): a concurrent-launch guard in
  `useDaemon.submit`, the document-creation repository scope in the shell's
  `DaemonClient`, a bound on the launcher's `Ping`/`Pong` exchange, and
  `models add`'s profile inheritance narrowed to an unchanged endpoint.
- The second review round (eight more bot findings, each fixed with a test):
  the aggregate model failure now speaks only for what its candidates agree on,
  the terminal client's endpoint probe travels the outbox like every other
  effect, `doctor` correlates local models by catalog id, the desktop's
  question card resets on a reissue and lets a typed answer replace a radio
  pick, the shell's workspace is persisted so a reconnect keeps its knowledge
  scope, a scoped plugin enable names its missing session, and a corrupt
  `auth.json` fails readiness instead of reading as empty.
- The third review round (three more findings): the probe's local-endpoint
  shortcut now compares the PARSED HOST via a shared
  `models::is_local_base_url`, so a remote host whose URL merely contains
  "localhost" is never probed with its credential during the credential-only
  pass (the desktop's own copy of that test is replaced by the same helper); a
  document block is re-read once its lease is HELD, so a full replacement
  cannot delete a concurrent writer's edit; and a failure card's Retry offers
  the objective of the run that FAILED, tracked per run id, rather than
  whichever run the surface happens to be showing.
- The fourth round (two more): a knowledge read scopes itself by the LIVE
  connection's repository rather than the freshly persisted selection, so a
  changed repository cannot list one checkout while a create writes into
  another; and the question card's reset signature covers the prompts
  themselves, not just how many there are, so a reissue that only changes the
  options cannot carry a pick the agent no longer offers.
- The fifth round (four more): the failure sanitiser redacts a credential
  inside a compact JSON body — `{"Authorization":"Bearer …"}` was rendered
  verbatim because the key-then-value rules never saw a value with no space
  before it — fixed in BOTH the TUI's sanitiser and the desktop's port; the
  daemon probe propagates a corrupt `auth.json` instead of reading it as
  empty; an aggregate failure is retryable when ANY candidate is, because an
  identical retry re-walks the whole list; and `reconnect()` resolves on the
  connection it started rather than on a counter, so the repository view
  cannot report a success that has not happened (or happened and failed).
- The sixth round (three more): a run that fails BEFORE the agent loop —
  no model configured, an unset credential, an unreachable endpoint, the
  commonest failures a new operator meets — now carries its classification to
  the terminal event, where `fail_run` had written `error: None`
  unconditionally; the desktop drops its repository-scoped surfaces when a
  reconnect rebinds the repository, so a stale Docs card cannot address a
  checkout the operator has left; and a sibling run's question no longer
  reports the DISPLAYED run as waiting for an answer.
- The seventh round (two, both in the previous round's own work): the
  composer clears its draft only while the box still holds what was SENT, so
  an objective typed during the round trip is not deleted; and the
  disconnected banner's Retry consumes the reconnect rejection it discards,
  which `reconnect()` only started producing when it was given a real outcome.
- The eighth round (three fixed, two answered as larger asks): the patch card
  reads the protocol's `preview`, not the `diff_preview` the client and its own
  test had both invented, so the diff was always empty against a real daemon;
  a question RESOLUTION is attributed to the run that asked, since the event
  carries no run id; and a repository-scoped read discards its answer when the
  connection changed while it was in flight, which dropping the surfaces alone
  did not cover. Two were referred back rather than pushed: associating an
  approval with its run needs `run_id` on `ApprovalRequested`/`ApprovalResolved`
  (a wire change), and adopting a live sibling when the focused run ends needs
  a live-run set in the store, which is a new state concept rather than a local
  fix.
- The ninth round (two): redaction follows a credential value to its closing
  quote, so `Basic`, `Digest` and every other authorization scheme is covered
  rather than `Bearer` alone — which the earlier fix caught only by accident,
  because the key word happens to END with it; and preferences that cannot be
  persisted now yield a process-stable workspace instead of `None`, which had
  the daemon minting a fresh one per connection and moving the knowledge scope
  on every reconnect.
- The tenth round (five): the retry row sanitises its provider message, which
  a proxy can fill with the request's own `Authorization` header; redaction is
  bounded by the LINE rather than a word count, so a multi-parameter `Digest`
  header no longer leaks its nonce and response; `ModelUsage` carries each token
  dimension as an `Option`, so an unreported one is absent rather than a
  fabricated `0 in`; the pinned and routed model checks keep their typed cause;
  and every read-modify-write of `desktop.json` runs under one lock, so two
  overlapping commands cannot erase each other's field.
- The eleventh round (three): reading a stored workspace no longer requires
  the write to succeed, so read-only storage keeps its identity instead of
  being handed a fresh one — a regression the tenth round's own locking fix
  introduced; JSON credential values are followed past their ESCAPED quotes,
  which had ended redaction at the first `\"` and printed the rest; and the
  local-endpoint probe requires the parsed host to be loopback rather than
  trusting a provider's `local` flag, which a `providers.toml` override could
  point at a LAN or public host.
- The twelfth round (two): every write of `auth.json` now runs under a hold
  that spans processes, so the desktop shell and the CLI saving credentials at
  once can no longer discard each other's key; and the API Keys page enumerates
  the ids the STORE holds rather than the catalog's, so a key left behind by a
  deleted custom provider stays visible and removable.
- The seventeenth round (one): `X-API-Key:secret` — a header written without
  RFC 9110's optional whitespace — kept its value in the SAME word, and every
  rule in the sanitizer redacts a FOLLOWING word, so the credential printed.
  `password:` and `secret:` had the identical gap. This is the second finding
  of this exact class: the sixteenth round fixed it for `Authorization` and
  left the rule next door untouched. The name before the first colon is now
  kept as context and everything after it redacted, in both sanitizers.

  That makes seven credential-leak holes in this one function across the
  branch, each fix correct for its case and none of them wrong about the
  grammar the values actually have. The word-splitting approach cannot
  express "a quoted string with escapes" or "a header value to end of line",
  which is what these inputs are; a small tokeniser for those two shapes would
  replace the guessing. Raised with the author rather than done unasked — it
  is a rewrite of a security-relevant function in two languages, and this PR
  is already large.
- The sixteenth round (three, plus a CI miss of my own): the Models and API
  Keys rows reported "Missing" for a model resolvable from the PROVIDER-wide
  key `add_model_in` deliberately stores, or from a documented provider
  environment variable — the projection claimed to mirror the TUI's and had
  two of its four steps; the desktop's launch-status probe was bound during
  render, so every unrelated parent render re-fired it while disconnected; and
