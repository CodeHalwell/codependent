## 1. The class fixes

### Repository identity — review §1.1

The invariant, now written down and enforced by the type: **a run has one
durable repository identity, and it is the checkout.**

- `crates/runtime/src/agent.rs` — the backing field is **private**. Readers go
  through `repository_identity()` (scope anything that touches the knowledge
  fabric) or `declared_repository()` (the offering gate). The working directory
  is now called `read_root`, so no call site can reach for a field named
  `repository` and get the wrong one. Routed through it: `docs.create/read/edit/
  suggest`, `graph.ask`, the three `graph.*` proposed actions, `skills.search`.
  All ten `run.worktree` uses (file I/O, `shell.run`, `git.*`) were classified
  and deliberately left as the working directory.
- `crates/cli/src/repo_anchor.rs` (new) — one accessor in two shapes, with a
  test asserting the path axis and the id axis resolve the same root so they
  cannot drift. Behind the board (4 sites — the review named 2) and `skill add`.
- `crates/codypendentd/src/blackboard.rs` — a relative repository path is
  resolved against the checkout or **refused**, instead of silently landing on
  the daemon's own cwd.
- `crates/runtime/src/agent.rs` — the transitional alias `with_board_repository`
  was deleted once the daemon moved off it, in the integration pass. A second
  way to set identity is how this bug comes back.

**Measured on the final integrated tree**, default Build mode, fresh data dir:

```
$ codypendent run --jsonl --objective "document the charge path …"
docs.create … RunUsage prompt_tokens:4000 completion_tokens:2000

$ codypendent docs list          # from the repo root
019ffdc2-d426-7430-bd9d-579549727a96   draft   1   Charge path runbook
$ cd src && codypendent docs list # from a subdirectory
019ffdc2-d426-7430-bd9d-579549727a96   draft   1   Charge path runbook
```

Before the fix this document was written into the run's throwaway worktree and
`docs list` answered `No documents yet.` — permanently, from anywhere.

### Ownership on the wire — review §2 row 19

Twelve per-arm `reject_unowned_*` calls became **one choke point ahead of
dispatch**, driven by `CommandBody::named_resources()` — an exhaustive match
with no wildcard, living in the crate that defines the enum precisely so a new
variant is a compile error rather than a silent "names nothing".

That closed `PublishDocument` (the reviewer's cross-uid confused deputy and
enumeration oracle) and `ReleaseDocumentLease` (no holder check), and the sweep
found a surface **the review had not**: `InstallUiPlugin` put arbitrary code
into the worker runtime gated only on a `ClientRole` the client asserts.

Verified cross-uid against a live daemon — a real document and an absent one now
give byte-identical refusals:

```
PublishDocument(uid 0's REAL doc) -> document.not-found 'no document 019ffda4-…'
PublishDocument(ABSENT doc)       -> document.not-found 'no document 099ffda4-…'
```

### Ceilings that were advisory — review §2 row 12

`crates/sandbox/src/wasm.rs` checked the wall clock **only** on the out-of-fuel
path, so a guest looping on host calls never reached the check. The reviewer
measured a declared 1s ceiling overrun by **166.8 seconds**, returning `Ok`.

```
BEFORE  RESULT Ok:  … duration 166.778777417s   (declared wall = 1s)
AFTER   RESULT Err: wasm guest exceeded its wall-clock ceiling (1s)
        REAL elapsed = 1.003909277s
```

Also: host work now costs fuel (a second, independent bound); a package can no
longer promote itself to `TrustTier::FirstParty` with one line of its own TOML
(every on-disk package is `Community`); the host-read budget is accounted
*before* the copy that can fail (the reviewer pulled 9.3 GiB metered as 0); and
the documented guest ABI now matches the arity the loader actually requires.

### The gate that measured nothing — review §1.3

`evals/ci/run_gate.sh` scored **3/13** and printed `PASSED`. The stub model
picked its scripted step by counting `[tool result:` markers, and the daemon
seeds `[tool result: context.assemble]` on the first call — so step 0 of every
case was skipped. The three "passing" cases were the three built entirely from
`file-unchanged`, which pass if the harness does nothing.

Now: the stub counts its **own** turns; the comparator fails on a score change
in *either* direction, on a changed case-id set, on corpus size, on a fail→pass
flip, and on a case file that produced no result; and `Assertion::
requires_observed_action` enforces at the **type** — exhaustive match, no `_`
arm — that every shipped case carries at least one assertion that cannot pass
unless work was really done.

Verified independently by the orchestrator, on the integrated tree:

```
$ bash evals/ci/run_gate.sh
eval: 13/13 case(s) passed (100%)
OK: 13/13 (1.0000) matches the baseline exactly, case for case
eval regression gate: PASSED                    GATE_EXIT=0

$ rm evals/tasks/core/011-readme-only-update.json && bash evals/ci/run_gate.sh
                                                GATE_EXIT=1
```

That deletion is the reviewer's original attack. Against the old comparator it
returned `success rate 1.0000 (3/3) … PASSED, EXIT=0`.

### Tokens reach the user — review §2 row 20

The daemon measured usage, stored it, put it on the wire and gave it a golden
vector; the TUI had no reducer arm, so every completed run printed the literal
words `? unsupported event` into the chat transcript. Now folded into
`RunView`, rendered in the header, footer, Run detail, the run's own completion
row and the accessible client, and `--jsonl` drains the usage event instead of
returning at `RunCompleted`:

```
   ✓ completed  ·  1,234 in · 567 out
  model stub/fast · Build · ctx 2/98% · … · 1,234 in · 567 out
```

The one failing test is
`daemon::remote_ui_plugins::tests::trust_removal_preserves_affected_ids_when_record_repair_fails`.
It `chmod 0o500`s a directory and expects the write to fail; **this container
runs as uid 0, and root ignores directory permissions.** Proven rather than
asserted — same binary, same tree:

```
$ setpriv --reuid=65534 … /tmp/dtest <that test> --exact
test result: ok. 1 passed
$ /tmp/dtest <that test> --exact          # as root
test result: FAILED. 0 passed; 1 failed
```

The file is byte-identical to the reviewed commit and nobody touched it this
round. CI runs as a non-root user, where it passes.

**CI itself could not be consulted.** `.github/workflows/ci.yml` triggers only
on pushes to `main` and on `pull_request`, and there is no `workflow_dispatch`;
opening a PR was out of scope. Every CI job's command was run locally instead,
which is what the table above is.
